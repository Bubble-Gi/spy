Файлы ищутся по именам: `sirena*.tab`, `BoardingData*`, `PointzAggregator*`,
`SkyTeam-Exchange*`, `FrequentFlyerForum*`, `Skyteam_Timetable*.pdf`, `*.xlsx`.
Любой можно указать явно: `--sirena`, `--boarding-data`, `--pointz`, `--exchange`,
`--forum`, `--timetable`, `--passes-dir`.

Полезные ключи:
- `--workers 11` — процессов для разбора PDF (по умолчанию ядер − 1);
- `--skip-timetable` — без расписания (колонки `timetable_check`, `aircraft` будут пустыми);
- `--tmp-db path` — где держать временную SQLite-базу (нужно ~1–2 Гб на диске);
- `--keep-db` — не удалять её после работы;
- `--soft-fields codeshare,ff_card_used` — поля, расхождение в которых НЕ делит поездку
  на две строки (оба значения пишутся через ` | `); по умолчанию все поля строгие;
- `--buffer-mb 8` — буфер чтения файлов в Мб;
- `--pass-sheets 200` — сколько листов талонов читается за одну порцию
  (в памяти одновременно не больше 2 × workers порций).


Рядом с CSV:
- `flights_clean.csv` — итог: `;`, UTF-8 с BOM, одна строка = один перелёт одного человека;
- `report.txt` — сколько прочитано, склеено, отброшено и почему, флаги, проверка по расписанию;
- `errors.log` — примеры строк, которые не удалось разобрать.

## Правила склейки

Люди:
- имена приводятся к латинице ИКАО (как в загранпаспорте), ВЕРХНИЙ регистр;
  варианты транслитерации (LIDIYA/LIDIIA, YURY/IURII) считаются одним именем;
- пустое поле не противоречит заполненному — дополняется;
- два заполненных разных значения (дата рождения, документ, пол, ник, uid,
  номер карты в одной программе) — разные люди;
- отчество-инициал `E.` совместимо с полным `EMILEVNA`;
- если человек подходит к нескольким сразу, решает общая карта / документ / uid / ник,
  а затем общий билет или тот же рейс в ту же дату;
  если и это не помогает — отдельный человек с флагом `identity_ambiguous`;
- записи без ФИО (только номер карты: SkyTeam-Exchange, форум) приклеиваются к человеку
  с этой картой; не нашлось — отбрасываются.

Перелёты (человек + рейс + дата):
- совместимые записи из разных источников склеиваются в одну строку;
- если хоть одно заполненное поле различается — две строки с флагом `conflict`.

## Флаги (колонка `flags`)

| флаг | значение |
|---|---|
| `ticket_suspicious` | номер билета не из 16 цифр |
| `ticket_shared` | один билет у нескольких разных людей |
| `ticket_damaged` | в одном из источников билет испорчен Excel'ем (`7,33391E+15`); если нашёлся полный номер — он и записан |
| `multi_leg_flight` | один номер рейса с промежуточной посадкой: строки — разные плечи, а не противоречие |
| `conflict` | одна поездка пришла с противоречащими данными, оставлены обе версии |
| `identity_ambiguous` | человек подходил к нескольким людям сразу |
| `name_restored_by_card` | ФИО подставлено по номеру карты |
| `airport_restored` | `rea`/`REA` заменён на `ICN` |
| `from/to_airport_by_city` | код аэропорта найден по названию города |
| `from/to_airport_by_timetable` | код аэропорта найден по расписанию |
| `time_by_timetable` | время взято из расписания |

## timetable_check

| значение | смысл |
|---|---|
| `confirmed` | дата в периоде расписания, рейс летает по этому маршруту в этот день |
| `wrong_day` | рейс на маршруте есть, но не в этот день / не в эти даты |
| `not_found` | дата в периоде расписания, а такого рейса на маршруте нет |
| `route_only` | дата вне периодов расписания, но рейс на этом маршруте в расписании есть |
| `not_found_out_of_period` | дата вне периодов, рейса в расписании нет |

«Нет в расписании» не значит «рейса не было»: расписание покрывает только свои периоды
(они перечислены в `report.txt`).
