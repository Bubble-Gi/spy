# find_suspicious: поиск подозрительных пассажиров

Скрипт анализирует склеенный файл `flights_clean.csv`: одна строка соответствует одному перелёту одного человека. Он ищет аномалии и формирует CSV-файлы с находками, списками пассажиров, связями и статистикой; достоверно установленные шпионы выводятся в отдельный файл `spies.csv`. Эти результаты предназначены для дальнейшего использования в приложении.

Склейку пассажиров выполняет пакет `flightparser`. Скрипт `find_suspicious` не пересматривает исходную склейку: **один `person_id` считается одним человеком**.

## Запуск

Установить зависимости:

```bash
pip install pandas numpy
```

Запустить анализ:

```bash
py find_suspicious.py --input flights_clean.csv --outdir results
```

Чтобы переопределить параметры `CONFIG` из JSON-файла:

```bash
py find_suspicious.py --input flights_clean.csv --outdir results --config my_config.json
```

## Главное правило идентификации

**Один `person_id` = один человек.** Все проверки связывают результаты с `person_id`: сравнивают перелёты одного человека между собой или сопоставляют разные `person_id` по документам, билетам и картам часто летающего пассажира (FF-картам).

## Работа с паспортами

Паспорта **не фильтруются по регулярному выражению или длине**. В проверки поступают все непустые значения `travel_doc`, кроме явных текстовых обозначений отсутствующих данных (`NA`, `NAN`, `NONE`, `NULL`, `UNKNOWN`, `NOTAVAILABLE`, `NOTPROVIDED`). Это означает, что значения нестандартного формата, с буквами или необычной длиной тоже участвуют в поиске совпадений. Скрипт не подтверждает, что каждое значение действительно является действительным паспортом.

Для сопоставления создаётся нормализованный ключ: Unicode приводится к совместимому виду, буквы — к верхнему регистру, пробелы и знаки форматирования убираются. **Ведущие нули при точном сравнении сохраняются.** Поэтому `0058 142289` и `58 142 289` не считаются одним и тем же точным ключом.

При этом скрипт отдельно ищет цифровые значения, которые совпадают после удаления ведущих нулей. Такая проверка называется `1b`: она создаёт **кандидат на совпадение**, но не объединяет номера и сама по себе не доказывает, что это один документ.

Паспортные значения собираются из **всех строк одного `person_id`**. Полный набор используется в проверках общего паспорта (`1`), общего билета (`5`), FF-карты (`6b`) и в сопоставлениях проверки `6a`. Поэтому одно значение документа не теряется только из-за того, что в другой строке человека указан иной документ.

Есть два важных ограничения:

- Значения, различающиеся только ведущими нулями, учитываются как варианты одного семейства в отдельных проверках, но в точном сопоставлении остаются разными. Такие пары отражаются в `1b`.
- Группы, где один паспорт, билет или FF-карта связаны более чем с `max_group` людьми (по умолчанию 50), пропускаются в соответствующих сравнениях как потенциальные заглушки или чрезмерно общие идентификаторы. Это ограничение по размеру группы, а не проверка формата паспорта.

В `suspicious_high.csv`, `suspicious_low.csv` и `findings.csv` поле `travel_doc` содержит уникальные исходные варианты документов, собранные из строк соответствующего `person_id`; варианты объединяются разделителем ` | `. Для поиска используется нормализованное представление, поэтому отображаемое значение может выглядеть иначе, чем ключ сравнения.

## Выходные файлы

| Файл | Что содержит | Предполагаемое использование |
|---|---|---|
| `spies.csv` | Шпионы: люди с высокой находкой в проверке `1` (общий паспорт при различающихся фамилии и дате рождения), одна строка на человека | Главный результат, показывать первым |
| `suspicious_high.csv` | Пассажиры класса `high`, одна строка на человека; шпионы из `spies.csv` сюда не входят | Список подозреваемых |
| `suspicious_low.csv` | Пассажиры класса `low`, одна строка на человека | Второй список для проверки |
| `findings.csv` | Все находки; одна строка соответствует отдельной находке | Детали и основания в карточке человека |
| `associates.csv` | Люди без собственных находок, которые не менее трёх раз летали вместе с человеком из класса `high` или со шпионом | Связи и окружение |
| `cotravel_pairs.csv` | Пары людей, летавших вместе не менее трёх раз | Граф связей |
| `timetable_coverage.csv` | Покрытие расписания по авиакомпаниям | Контекст для проверки `3a` |
| `summary.csv` | Статистика входных данных, находок, классификации и времени выполнения | Страница «о данных» и диагностика |

### `spies.csv`

Шпионы устанавливаются по паспортному признаку, который считается надёжным: у разных `person_id` совпадает нормализованный паспорт, а фамилия и дата рождения у них обоих различаются (находка `1` уровня `high`). Каждый такой человек попадает в `spies.csv` и **не дублируется** в `suspicious_high.csv`.

Колонки те же, что в `suspicious_high.csv` (описание ниже), но в `class` стоит `spy`. Все находки шпионов остаются в `findings.csv`, а люди, летавшие вместе со шпионами, попадают в `associates.csv`. Правило задаётся параметром `spy_subchecks` в `CONFIG` (по умолчанию `["1"]`). Подпроверка `1b` и основания `6a` под него не подпадают.

### `suspicious_high.csv` и `suspicious_low.csv`

| Колонка | Значение |
|---|---|
| `person_id`, `last_name`, `first_name`, `middle_name`, `birth_date`, `travel_doc`, `ff_cards` | Данные пассажира из склеенного набора; значения документов и FF-карт собираются из строк человека, многозначные значения разделены ` \| ` |
| `ambiguous_identity` | `True`, если не менее доли строк, заданной `ambiguous_share` (по умолчанию 50%), содержит флаг `identity_ambiguous`. Такой `person_id` мог появиться из-за неоднозначной склейки |
| `class` | `high` или `low` |
| `n_high`, `n_medium`, `n_low` | Число находок каждого уровня |
| `checks` | Сводка находок по подпроверкам и уровням, например `2a:high x1; 2d:low x9; 5:low x1` |
| `top_evidence` | До трёх наиболее сильных оснований, текст через ` \|\| ` |

Наличие `ambiguous_identity` само по себе не понижает уровень находок: `downgrade_ambiguous = False`.

### `findings.csv`

| Колонка | Значение |
|---|---|
| `person_id`, `last_name`, `first_name`, `birth_date`, `travel_doc` | Пассажир и собранные варианты документа |
| `check` | Номер проверки (`1`, `2`, `5`, `6`, `9` и т. д.) |
| `subcheck` | Подпроверка (`1b`, `2a`, `2d`, `9c` и т. д.) |
| `level` | Базовый уровень: `high`, `medium` или `low` |
| `level_effective` | Уровень после возможного понижения из-за `identity_ambiguous`; при текущем `downgrade_ambiguous = False` совпадает с `level` |
| `ambiguous_identity` | Признак неоднозначной склейки |
| `flight`, `date` | Рейс и дата, если находка относится к конкретному перелёту; дата в формате `дд.мм.гггг` |
| `evidence` | Текстовое объяснение на английском языке с деталями срабатывания |

Чтобы показать полную запись перелёта, используйте `person_id` и, если они заполнены, `flight` и `date` для поиска соответствующих строк в `flights_clean.csv`. Для находок, относящихся к человеку в целом, рейс и дата могут быть пустыми.

### `associates.csv`

Человек, у которого нет собственных находок, но который не менее трёх раз летал вместе с человеком класса `high` или со шпионом из `spies.csv`.

Колонки: `person_id`, `last_name`, `first_name`, `linked_to` (идентификатор подозреваемого или шпиона), `shared_flights` (число совместных перелётов).

Это пометка для приложения, а не отдельная находка. Родственники отдельно не определяются. В файле могут встречаться люди с теми же именами, что у подозреваемого: список не пытается решать, являются ли они одним человеком, ошибочно разделённым на разные `person_id`.

### `cotravel_pairs.csv`

Пары людей, летавших одним и тем же рейсом в одну дату не менее трёх раз. Рейсы, где более 30 разных `person_id`, исключаются. Колонки: `person_a`, `person_b`, `shared_flights`. `associates.csv` — отфильтрованная часть связей, касающаяся пассажиров класса `high`, шпионов и людей без собственных находок.

### `timetable_coverage.csv`

Для каждой авиакомпании содержит `rows` (число перелётов без кодшера), `not_found` (число не найденных рейсов), `coverage` (доля найденных) и `checked` (участвует ли авиакомпания в проверке `3a`). PDF-расписание относится к периоду 01.11.2018–31.01.2019, тогда как анализируемые рейсы относятся к 2017 году. Поэтому расписание используется только как справочник маршрутов; дата рейса по PDF не проверяется.

### `summary.csv`

Колонки: `section;key;value`.

- `input` — параметры входного файла, количество строк и `person_id`, статистика документов и билетов, пропущенные большие группы, непарсящиеся даты рождения, значения статусов и расписания.
- `findings` — количество находок и людей по каждой подпроверке и уровню.
- `classification` — размеры списков `spies`, `suspicious_high` (без шпионов), `suspicious_low` и `associates`.
- `seconds` — время выполнения анализа.

В секции `input` есть отдельные показатели для паспортов, собранных по всем строкам человека, паспортов в первом выбранном непустом поле и возможных совпадений после удаления ведущих нулей. Показатели `persons_with_invalid_doc_only` и `invalid_doc_examples` больше не используются: паспорт не отбрасывается только из-за формата.

## Как человек попадает в список

- **Шпионы (`spies.csv`):** хотя бы одна находка эффективного уровня `high` в проверке из `spy_subchecks` (по умолчанию проверка `1`: общий паспорт, различаются и фамилия, и дата рождения). Такие люди выводятся только в `spies.csv`.
- **Очень подозрительные (`high`):** хотя бы одна находка эффективного уровня `high` либо не менее трёх находок `medium`, относящихся к трём разным проверкам; люди, ставшие шпионами, в этот список не входят.
- **Немного подозрительные (`low`):** хотя бы одна находка `medium` либо не менее двух находок `low` по двум разным проверкам, если человек не попал в `high`.
- Одиночная находка `low` остаётся в `findings.csv`, но не включает человека в списки.

Пороги задаются параметрами `high_min_medium`, `high_min_medium_checks`, `low_min_low` и `low_min_low_checks` в `CONFIG`.

## Проверки

В таблице указан базовый уровень находки. Уровень `medium` может участвовать в итоговой классификации `high` при выполнении общего порога по трём разным проверкам.

| Подпроверка | Что ищет | Уровень |
|---|---|---|
| `1` | Один и тот же нормализованный паспорт у разных `person_id`. Различаются фамилия и дата рождения — `high`; различается только одно из них — `medium`; ни то ни другое — `low`. Сравнение фамилий использует настроенную нормализацию окончаний. Даты, отличающиеся только перестановкой дня и месяца, по умолчанию считаются потенциально одной датой; если других отличий нет, находка подавляется (`birth_swap_level = none`). Находка уровня `high` делает человека шпионом (см. `spies.csv`) | `high` / `medium` / `low` |
| `1b` | Цифровые паспорта разных людей, которые совпадают после удаления ведущих нулей, но не совпадают как точные нормализованные ключи. Это кандидат на совпадение, а не доказательство тождественности документа | `low` |
| `2a` | У одного человека совпадают дата и время вылета, но рейсы различаются | `high` |
| `2b` | Следующий рейс вылетает раньше прилёта предыдущего, при этом стыковка выполняется в одном аэропорту | `medium` |
| `2c` | В один день человек вылетает из одного аэропорта разными рейсами в разные места, и среди записей нет обратного вылета в исходный аэропорт | `medium` |
| `2d` | «Телепортация»: последний аэропорт одного дня отличается от первого аэропорта следующего дня с перелётами. Проверяется только при разрыве не более `teleport_max_days` (по умолчанию 2 дня) | `low` |
| `3a` | Рейс не найден в справочнике маршрутов. Проверка выполняется только для авиакомпаний с покрытием не ниже `timetable_min_airline_coverage` (по умолчанию 95%), не менее `timetable_min_airline_rows` строк (по умолчанию 200) и без кодшера | `medium` |
| `3c` | Маршрут есть в расписании, но рейс помечен как выполняющийся не в этот день (`wrong_day`) | `medium` |
| `4` | Один билет связан с одним рейсом, но в данных отличаются дата или время вылета. Даты выписки билета в файле нет | `medium` |
| `5` | Один билет использован разными `person_id`. Несовместимые наборы паспортов — `high`; если высокого конфликта документов нет, но различается сигнатура из нормализованной фамилии и первой буквы имени — `medium`; иначе — `low`. Для сравнения используются документы, собранные по всем строкам человека, с учётом семейства цифровых номеров без ведущих нулей | `high` / `medium` / `low` |
| `6a` | Два основания. `high`: в первом выбранном непустом значении `travel_doc` для человека содержатся несколько различных паспортов (варианты только с разными ведущими нулями не считаются разными). `medium`: у разных `person_id` совпадают полные фамилия, имя, отчество и точная дата рождения, но отличаются паспорта за исключением различий только ведущими нулями. Второе основание рассматривается как неоднозначность личности, а не автоматическое высокое подозрение | `high` / `medium` |
| `6b` | Одна FF-карта связана с людьми с несовпадающими наборами паспортов; для сопоставления учитываются все собранные документы | `medium` |
| `7` | У одного человека для одного рейса и даты указаны два или более разных билета | `medium` |
| `8a` | Разные значения пола у людей с одним паспортом либо несколько противоречивых значений в многозначном поле пола одного человека | `medium` |
| `8b` | Возраст на момент перелётов меньше 0 или больше `max_age` (по умолчанию 100 лет) | `medium` |
| `9a` | Класс перелёта не совпадает с первой буквой тарифа | `low` |
| `9b` | Дата прилёта раньше даты вылета | `low` |
| `9c` | Аэропорты вылета и прилёта совпадают | `low` |
| `9d` | Для одного рейса есть противоречивые данные; учитывается флаг склейки `conflict` | `low` |
| `10a` | Слишком много перелётов за месяц: порог строится по 99-му перцентилю; минимальное число перелётов для срабатывания — `freq_month_min` (по умолчанию 6) | `low` |
| `10b` | Слишком много перелётов за всё время: порог строится по 99-му перцентилю; минимальное число перелётов для срабатывания — `freq_total_min` (по умолчанию 20) | `low` |
| `10c` | Прилёт в редко посещаемый аэропорт, куда прибывали не более `rare_airport_max_people` разных людей (по умолчанию 3) | `low` |
| `11` | Совместные перелёты: это не самостоятельная находка; информация попадает только в `associates.csv` и `cotravel_pairs.csv` | — |
| `12` | Статус рейса указан как отменённый (`CANCELLED` или `CANCELED`) | `medium` |

Строки с флагами `conflict` и `multi_leg_flight` не участвуют в проверках перемещения `2a`–`2d`.
